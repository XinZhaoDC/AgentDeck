# 客户端账号、历史与环境配置（0.12.0）

## 历史设置操作布局（0.12.14）

“数据与存储 → 历史标签设置”先显示全宽“历史标签管理…”按钮及简短说明。Codex 的“升级/刷新原生历史索引”是另一个独立全宽按钮，下方说明索引用于本环境文件定位、不改变历史选择范围，添加/移除会自动更新；手动操作前结束任务，完成后重载。旧索引状态单独短提示。Claude Code 直接扫描项目历史，不显示索引按钮和专属说明；标签管理两页共用。API来源配置与首次信任指引保留在“API 来源记录说明”折叠项中。

## 新 API 聊天自动来源（0.12.12）

两个客户端均可把之后创建的 API 聊天按具体 API 名称作为一级来源，再按环境、项目分组；底层仍使用原来的一个 API 共享 profile，不按供应商新建或搬迁 profile。API 名称是新会话创建时的名称快照，记录同时保留当时供应商稳定 ID；同一客户端内名称相同的来源跨环境合组，名称比较去空白、统一兼容字符并忽略大小写。API 重命名后新聊天使用新名称，旧聊天保留创建时名称，仍可用标签管理整理。

使用前先连接数据目录和 API 档案，升级后重新应用当前 API，再重载窗口/重启使用同目录的 CLI。AgentDeck 将一个来源记录器加入该 API 的原生 SessionStart hook，和 API 配置一起事务保存。以后 API 切换仍按原流程应用并重载，不需要逐次手动归类。它记录新建 startup、clear、fork 事件；续聊 resume、压缩 compact 不重新认领旧来源，索引扫描和导入副本也不会被当成新的 API 聊天。跨环境的事件写入各自会话 ID，浏览历史时不以当前 API 猜来源。

**Codex 首次需要在使用该 CODEX_HOME 的原生 CLI 输入 `/hooks`，检查并信任 AgentDeck 来源记录命令，再开始新聊天。**原生扩展若提供 Review hooks 入口也可在那里完成。信任保存在当前环境；AgentDeck 不写信任记录或开启 bypass。未信任、hooks 被用户/策略关闭、来源写入失败、旧版本不支持事件时，聊天仍正常保留，但归“来源未记录”；补信任不会追溯重分旧聊天。命令在切换 API 时不变，通常不需重新审核；扩展升级导致脚本/路径变化时按原生提示重新审核。Claude 使用自己的 SessionStart hooks，若关闭同样不能自动记录。

依据：[Codex hooks / trust](https://learn.chatgpt.com/docs/hooks)、[Claude Code hooks / SessionStart](https://code.claude.com/docs/en/hooks)。这是“由 AgentDeck 应用的 API 设置＋原生新会话事件”的创建来源记录，不是逐请求账单审计；外部手工改配置、单次 CLI 覆盖地址/密钥、项目配置覆盖或旧进程未重启不保证能反映实际请求供应商。通过 AgentDeck 应用并重启是此功能的使用边界。

旧的未知历史继续放在“来源未记录”；已有手动归类保留，并优先于自动记录。手动指定“来源未记录”可覆盖自动分组。官方帐号仍按原帐号 profile 划分，不会被归入 API。Codex 与 Claude 的数据根、配置、认证和网络继续独立。

API 配置目录的 .agentdeck-api-source.json 只保存当前环境/档案/API ID 与名称，不保存 Key、URL 或令牌；profiles/home-<ID>/history-sources/<会话ID>.json 保存不可覆盖的新会话来源记录，含创建环境与时间。归档文件移动后按会话 ID 仍可识别；原聊天正文不改。共享记录文件0660、目录2770，只创建自己的元数据，不修复其他用户权限。标签文件仍 history-labels.json；来源记录和标签均应随完整数据目录备份，history-only 备份不含 profile 旁的来源记录。

### 原生索引和选择历史项目的关系

可以把聊天文件看成书，“索引”是 Codex 用来找到书的目录，“选择历史项目”是决定把哪些其他档案的书加入当前原生列表。

- **升级/刷新索引**：为当前目标档案建立本环境可用的文件目录。例如容器的 /home/workspace/... 在宿主机不存在，修复后用宿主当前挂载路径找到同一份聊天；不会改变已选择的展示范围，也不会把所有其他帐号历史自动加入。
- **选择历史项目**：在 AgentDeck 扫描出的共享历史中多选，加入当前目标档案的独立副本；来源保留、新聊天位置不变。添加/移除时自动更新 Codex 索引，索引正常时无需每次先手动刷新。
- **Claude 没有此按钮**：当前原生读取器直接扫描当前项目的 JSONL 目录；添加/移除对应的展示副本即可，不使用 Codex 的 SQLite 路径索引。两页的选择、标签、管理功能仍一致，底层客户端机制不同。

## 标签页导航与环境说明（0.12.11）

历史标签管理的顶部提供帐号/来源、环境、项目、手动归类、结构树五个分区入口。导航或聚焦字段后，“当前位置”显示所在分区与原名；在树中聚焦则显示帐号/来源→环境→项目→聊天。一级蓝色、二级青绿色、三级紫色，配合不同深浅背景、编号和逐级缩进；原名/项目路径与可编辑的“显示标签”分别标明。勾选或编辑时保留树的展开状态；搜索临时展开匹配分支，清空搜索恢复先前状态。

环境列表展示数据目录中已登记的环境，不是扫描每条旧聊天后推断出的机器清单。当前截图有宿主和容器两个登记项；“环境未标注”表示旧会话缺少环境关联，属于待归类分组，不算第三个环境。项目路径本身不能可靠证明创建环境，不能仅按 /home/whistle 或 /home/workspace 自动认定；可在结构树勾选对应聊天后明确指定已登记环境，再保存。API“来源未记录”和“环境未标注”是独立的两项元数据。

Codex“升级/刷新原生历史索引”让原生程序扫描共享聊天文件，将本环境可用的路径写入独立的 SQLite 会话目录；跨宿主/容器时，共享聊天文件可读不代表旧索引路径可用。该操作也整理共享的会话名称记录，保留旧索引/名称文件，失败回退。它不会重新登录、调用模型或重新生成聊天；也不会补全旧聊天缺失的环境归属、给 API 历史推断供应商。结束正在运行的原生任务后再点击，完成后重载窗口。

## 统一历史标签与手动归类（0.12.10）

两个页面在“数据与存储 → 历史标签设置”打开“历史标签管理…”。页面上方设置三级标签，下方显示当前历史chat结构树并实时预览草稿；原生历史区域只保留选择、查看和管理已显示历史，不再单设环境标签按钮。

1. 一级为官方帐号或API来源。官方帐号按稳定profile ID保存显示标签；API历史来源未知时进入“来源未记录”，可新建来源名（支持从已有API名称选择）并填写显示标签。新建来源本身不会认定某聊天使用了它。
2. 二级为环境标签。同一个环境ID在所有帐号/API来源下复用一次标签；原始环境名称保持只读。
3. 三级为项目标签。同一环境ID＋完整项目路径在不同帐号/API模式下只设置一次。不同环境/路径属于同一项目时，在“复用项目标签”选择已有项目，之后修改共用标签会同步各分支，原路径仍分别显示。“独立设置”可解除标签复用；同名末级文件夹不会自动合并。
4. 填写标签后显示“标签名 / 原有名称”，清空标签恢复原名。下方结构树按官方帐号/API来源→环境→项目→聊天展开，支持搜索和批量勾选；这里只为归类勾选，不改变原生历史已添加状态。
5. 在树中勾选单条聊天、项目或环境，选择API来源和/或环境后点击“应用到勾选聊天”，最后“保存标签与归类”。API来源只作用于API历史；官方帐号保持自己的来源。选择“来源未记录”或“环境未标注”可清除对应明确归属，“保持不变”保留原值。
6. API来源可来自用户明确的手动归类（保存manual与时间）或0.12.12原生新会话收据，不从当前配置、密钥、URL或新增文件事件猜测旧聊天实际供应商。聊天使用不同API时可逐会话划分，即便同一物理API档案/项目也可以分多个来源。没有原生新会话收据的聊天继续未记录，可之后批量归类。
7. 标签和手动归属保存在当前客户端共享数据根history-labels.json，宿主/容器复用，同客户端的不同官方帐号/API模式共同使用。Codex与Claude各自保存，源profiles/ID、供应商名称/配置、登录、网络和聊天文件均不改。源项目不会被移动或物理合并；现有增量添加、灰显与多选移除保持。

标签保存后，历史选择与管理入口重新打开即显示最新标签；已添加历史的管理也按当前归类显示。原生会话自己的标题不强制重命名。关闭未保存页面会丢弃草稿；保存失败保留草稿。并发窗口/环境保存遇到旧版本会明确提示重新打开，避免覆盖他人更新。只写标签元数据，不需要重载原生扩展或重新登录。

“环境未标注”表示缺少可确定的历史关联记录。现有catalog中按工作区路径观察到的环境是浏览关联，不保证是会话唯一创建来源；需要明确来源时通过管理页手动指定。标签别名也不作为真实供应商或创建环境的证明。

history-labels.json与标签事务目录使用共享组0660/2770；不读取凭据、不修改其他用户属主/权限。标签/手动归属不在现有history-only备份中，应随完整数据目录备份。

## Codex普通名称索引升级（0.12.9）

## 多选历史与跨帐号协作（0.12.8）

两个页面均提供“选择历史项目…”“管理已显示历史…”“查看已添加会话…”；标签集中到数据与存储的“历史标签管理…”。连接相同数据目录后，无论当前是哪个官方帐号还是API模式，都可以浏览当前客户端全部官方/API档案的可读历史。Codex与Claude分别浏览各自历史，不混用客户端格式、认证或网络。

1. Codex若提示旧索引，先点击“升级/刷新原生历史索引”并重载。目录连接不代表索引已升级；原共享SQLite及聊天保留。
2. 点击“选择历史项目…”，树形层级为官方帐号／API模式→环境→项目→聊天。可勾选整组、多个项目或单条聊天，跨分支多选。当前帐号、当前环境、当前项目依次优先，其余按最近更新排序；支持搜索。选择页只做增量添加，已添加项灰显，不能在这里取消已有展示。
3. 未知旧来源归“环境未标注”；通过历史标签管理页手动归类及设置共用标签，原有名称同时显示。
4. 确认后生成当前目标档案中的独立会话副本，新会话编号与来源不同，来源档案只读。Codex副本使用当前供应商的原生索引，Claude副本放在当前项目的普通目录；新聊天始终保存到原来的位置。副本标题标明来源帐号与环境，AgentDeck打开入口也显示来源项目；正文通过官方扩展读取。
5. 改动后重载窗口、重启旧CLI，再从原生历史列表或“查看已添加会话…”打开。继续聊天使用当前登录帐号/API及当前路由，后续内容属于当前档案副本，不回写来源。副本是添加时的快照，不自动同步另一帐号后续新消息。
6. 在“管理已显示历史…”勾选任意多个对象并移除，重载后从原生列表隐藏。来源聊天保留，副本及续聊内容保留在目标profile的history-imports/中；之后重新添加同一来源会恢复保留副本。不会删除原生默认已有的聊天；这类条目在选择页标注“原生默认已有”。

展示范围遵循原生客户端：Codex为当前目标档案的全部项目，Claude为当前目标档案的当前工作区项目。相同原生范围的添加状态保存在目标profile中，跨环境看到同一范围时去重并可管理；不是各环境互相独立的聊天副本集合。多根工作区操作先选当前项目。帐号切换时使用另一目标profile自己的展示记录；跨帐号可读取来源，不会复用登录缓存。

### 共享权限与失败处理

读取来源只需要可读权限，不要求来源可写，不创建跨帐号硬链接。新副本/目录按共享组0660/2770创建，受保护硬链接策略不会阻止普通复制。目录与目标索引写权限在实际操作中检查，新增过程逐会话提交：不可读或损坏的对象单独报告，其余可继续添加。没有权限的源不会被偷偷放宽权限，也不通过root身份代替宿主运行。

父目录默认ACL不能覆盖原生显式0600文件；启动、连接和历史watcher继续维护写入者自己拥有的历史0660/2770，不进入认证/配置、不改其他用户文件属主或权限。建议宿主与容器两端都安装运行新版。读取端遇到其他用户0600文件，需要写入端运行新版或文件所有者修复；插件未运行时不是系统权限守护服务。

### 存储、回退与限制

已有profiles及ID保持不变：原始历史仍在profile/history，新增history-imports.json记录来源/展示状态，history-imports/保留隐藏副本；history-catalog.json保存环境关联。枚举排除受管副本，避免将其当成新的来源重复导入。当前历史备份包含可见副本；隐藏保留内容及其管理记录应随整个数据目录另行备份，当前“历史备份”不会打包profile旁的隐藏副本库。

Claude移除通过事务将副本移出原生projects扫描路径；Codex先提交保留副本，再调用原生thread/delete删除独立副本及索引。若RPC或状态发布失败，保留材料不会被回滚删除，管理页可重试。新选择不使用硬链接或整目录映射；检测0.12.6/0.12.7旧入口后，先到管理入口显式解除并重载，再多选。原生已替换的旧入口仍保留，旧版本恢复机制不改写。

原生列表自己的筛选仍由官方UI管理，必要时选择All chats。跨机器源消息中引用的外部附件/文件路径不保证可用，不自动搬迁项目文件；继续执行工具前确认当前工作区。Linux、当前安装原生读取器与合成历史已验证；真实GUI、实际模型续聊、Windows/macOS/WSL仍需验收。

## 添加供应商与名称联想

Codex 和 Claude Code 添加 API 供应商成功后，清空名称与 API Key，保留基本字段中的地址、模型及群组选择；失败时保留表单供修改重试。完整配置方式成功后重新生成无密钥的默认模板，不保留已提交的内联密钥。

名称框支持历史候选：例如保存过“启源星”，下次输入“启”可从原生下拉候选选择，再按需修改。两个客户端分别记忆最近100个成功保存的名称，已有 API 供应商名称也作为候选；仅名称写入页面状态，密钥和完整配置不会进入联想记录。页面状态恢复时保留名称历史；重名仍按当前客户端内唯一的规则校验。

## 0.12.2 请求处理与余额预设

两个页面同步使用图标群组折叠按钮，保留悬停提示与可访问标签。请求处理增加标准与流式兼容选项，余额查询统一群组／模板／供应商三处预设，明确 Key 额度和账户管理凭据；可展开调整参数且保留认证方式。使用步骤及各预设含义见 [API 请求与余额预设](api-presets.md)。原有规则升级时不自动覆盖，未配置群组的新供应商仍直接调用 API。

## 双客户端群组显示与名称

未特别说明的 UI 调整同时适用于 Codex 和 Claude Code，配置、网络、数据和界面草稿仍分别管理。每个供应商群组标题左侧有“展开／收起”按钮，默认展开；折叠后保留群组名、供应商数、开关和操作按钮。折叠状态按客户端与环境分别记忆，官方只读模式或群组禁用仍可折叠。点击“群组设置”会展开所属群组。

同一客户端内群组名唯一（包括“独立供应商”），API 供应商名在该客户端所有群组之间唯一；Codex 和 Claude 可以各自使用相同名称。比较会去除首尾空格、统一全角等兼容字符并忽略大小写，例如 Service、 service 和 Ｓｅｒｖｉｃｅ 视为同名。新增、群组重命名和导入按相同规则校验，重复则拒绝保存，不自动改名或合并已有供应商。群组名和供应商名属于各自的名称范围。

两客户端采用统一管理层级，配置、网络、账号及数据保持独立。历史正文交给各自原生客户端查看，AgentDeck 不浏览或搜索聊天正文。以下先说明 Claude 新行为，后部保留 Codex 的完整存储与迁移契约。

## Claude Code：账号、历史与登录状态（0.12.0）

Claude 页面现在采用与 Codex 一致的总览、数据与存储、网络、账号与 API 层级，以及群组、模板、默认地址、后台初始化、ON/OFF、长按拖动、单步箭头、局部反馈和内嵌编辑。请求配置使用 Claude 原生 JSON/Anthropic 协议；不会写 Codex TOML 或调用 Codex 官方额度接口。官方诊断引导在原生 Claude 执行 `/status`、`/usage`；API 模型目录、连接、余额和生成测速沿用公用 API 服务。

用户选择数据父目录后使用 `claude/`，与 `codex/` 分开。每个 claude.ai 官方订阅账号有独立档案；所有 Claude API 供应商共用一个 API 历史档案。共享 `profiles/home-<UUID>/history/projects/` 保存原生会话、会话辅助文件及原生项目记忆。配置、认证、绑定、操作日志和恢复记录按环境独立；备份只复制 projects 树，不复制 settings、OAuth 缓存或系统凭据。共享物理路径在不同系统可能对应不同项目路径，跨OS历史识别/文件锁仍需实机验收。

本环境为每个新档案准备固定的 `environments/<环境UUID>/homes/<档案UUID>/`。首次连接空数据根时可以直接采用原配置目录，保持原生登录缓存、目录路径和默认/显式环境变量语义，不读取或搬动 OAuth 缓存，也不访问系统凭据库。原 projects 保留为 `projects.before-vscodemodelswitch-*`，历史复制校验与目录接入在用户确认后执行。准备阶段或失败操作可能保留未启用档案/历史副本，不能据此删除原数据；重试同一根应选择已准备档案，不自动清空或合并后来产生的历史。

`CLAUDE_CONFIG_DIR` 是扩展和 VS Code 新终端的档案选择接口。默认档案保持该变量为空；显式档案使用绝对路径。原生 Claude 的登录缓存/系统凭据库和全局状态均继续由它维护，AgentDeck 不执行 `/logout`、不代替客户端刷新令牌、不恢复某次登录快照。因而官方 A → API → 官方 A、A → B → A 可以复用各自仍有效的登录状态，原生刷新不会被旧副本覆盖；用户明确退出后也不会恢复旧登录。首次登录、新环境、服务端撤销、过期且刷新失败及组织策略仍可能要求认证。Claude Console 不创建 API Key 的 OAuth 账号有原生目录外存储例外，本版不承诺这类 Console 多账号隔离。

切换前单次确认，提示先结束运行任务；改目录后需要重载扩展/重启旧 CLI。外部终端必须使用页面显示的目录选择语义。切换设置有私有持久恢复记录，文件事务和启动选择不一致时恢复自己的设置；检测外部修改则保留记录、阻止后续运行配置写入。网络先准备目标目录，冲突时不切换账号。模板不包含 API Key、余额令牌或用户 ID；删除模板保留已载入副本。

两客户端群组/供应商导出均为 v2，导入仅作用于当前页面客户端，不自动应用。Claude 操作日志在自己的环境目录，显示、导出和删除针对当前客户端；Codex 的旧 VS Code 输出通道仍是整个扩展共享输出，Claude 删除日志不会清空它。

参考：[Claude 登录与多账号](https://code.claude.com/docs/en/authentication)、[API 变量优先级](https://support.claude.com/en/articles/12304248-manage-api-key-environment-variables-in-claude-code)。网络与浏览器范围见[网络说明](network-proxy.md)。自动验证只用合成凭据及隔离 HOME，不替代真实订阅登录、刷新、系统凭据库或图形界面验收。

## 界面与操作顺序

插件显示名称为“AgentDeck”，原内部扩展标识及数据键保持不变。界面默认中文，保留 Codex、Claude Code、API、HTTP、JSON、模型 ID 等专有名称或技术表达。

Codex 页面按“总览 → 数据与存储 → 网络设置 → 账号与 API”排布。账号与 API 内包含登录方式、官方账号和 API 供应商。主模块、子模块使用统一的折叠边框；说明在标题下，固定注意事项以“ⓘ 注”区分。总览突出当前环境，配置按钮和终端按钮并排；配置管理开关不等于禁用官方扩展。

官方模式下 API 配置只读，API 模式下官方账号只读。账号切换、模式切换、活动历史绑定和实际网络设置变更显示持续待重载状态，成功后提供原生重载入口。每次启动做本地轻量核查后再清除；不扫描全部聊天或自动测速。API 内切换供应商的提醒保留约一分钟，也可手动关闭；只改模型不新建颜色提醒。

操作结果显示在对应模块或供应商上方，绿框成功、红框失败，十秒后消失；每个目标独立计时，新结果不会被旧计时器移除。文件恢复未完成的持续错误不受十秒计时影响。测试或单个供应商结果更新时保留其他卡片和未保存表单。

每个 API 供应商分别提供模型列表刷新、选择模型和真实验证；诊断分连接/模型目录/可选额度与三轮生成速度。首轮数据和三轮汇总分开，缓存、缓冲和失败状态仍保留。批量诊断可选择供应商，默认不发生成请求；消耗额度的测速显式选择。官方账号诊断仅查询当前账号的模型和额度窗口，或执行当前账号三轮测速，不切换其他账号。

顶部刷新只更新当前安装版本的状态，不会替其他容器安装新版。网络实现和 Linux 实验入口的兼容性限制见 [网络说明](network-proxy.md)。

供应商群组、模板、排序、禁用及新版配置格式见[客户端架构与群组](client-architecture.md)。所有 API 供应商仍使用唯一 API 历史档案，与群组无关。已连接数据目录后，在“账号与 API → 登录方式”点击“切换到 API”，自动创建或复用 API 档案，重载后应用供应商。另一环境连接同一目录时选择已有 API 档案，再重载及应用本环境供应商。当前新增档案默认名为“API 共享历史”；旧名称或用户别名保留。

## 存储结构与 CODEX_HOME

用户选择 `ai_client_data`，插件使用它的 `codex` 子目录；直接选择名为 codex 的目录也可以。

```text
ai_client_data/codex/
  readme.md
  profiles.json                         共享账号档案注册表，不保存活动选择
  profiles/home-<UUID>/history/
    sessions/                           共享原生聊天文件
    archived_sessions/
    sqlite/                             共享原生 SQLite 状态/索引
  providers/                            用户主动导出的公共定义
  environments/<环境UUID>/
    logs/                               本环境操作日志（自动轮换）
    binding.json                        本环境活动档案
    homes/<档案UUID>/
      config.toml                       本环境、该档案的配置
      auth.json                         本环境、该档案的登录缓存（登录后生成）
      sessions -> 对应共享历史目录
      archived_sessions -> 对应共享归档目录
    .recovery/current/                  仅操作期间存在；异常冲突时保留
  backups/codex-history-<UUID>/          用户主动备份
```

实际 `CODEX_HOME` 在 Linux 下若已是普通目录（包括 bind mount），保持根目录原位，只替换其中的历史子目录链接；入口原本是链接或尚不存在时，继续链接到本环境的账号 home。固定入口的 auth.json/config.toml 使用普通文件，切换时事务保存当前缓存并加载目标档案缓存，以兼容 Codex 原子替换认证文件。删除认证后再切回也不会恢复旧凭据。没有设置 CODEX_HOME 时使用当前执行端默认 `~/.codex`。用户自定义路径也可绑定。应让官方扩展与 CLI 的启动环境一致；在某个终端临时 export 不会更改已运行的 VS Code 扩展进程环境。

历史目录链接让后续新聊天直接写入共享存储，不是后台复制或两份同步。`sqlite_home` 写入每个环境自己的 config.toml，使用该环境看到的挂载路径，并覆盖 CODEX_SQLITE_HOME；应用 API Provider 时保留该路径。history.jsonl/session_index.jsonl 的原始副本随初次迁入保留，当前环境后续的辅助文本索引可各自维护；原生 Chats 的共享数据以 sessions/archived_sessions 和 SQLite 为准。

Linux 创建目录软链接；Windows 本地目录使用 junction。两端路径可以不同，但必须对应同一个物理目录。Windows 开启“让 Codex 运行于 WSL”时，应在对应 WSL 窗口运行本插件，Windows 端会阻止修改错误的 home。Windows UNC/网络共享不保证能创建 junction；失败明确提示并恢复入口，不自动换一种未经验证的共享方式。数据库不能通过云盘逐文件实时同步替代可靠挂载。跨 Windows/Linux 的绝对项目路径、数据库路径与文件锁兼容性仍需实机验收；列表可见不代表另一个环境有原项目工作目录。

## 总览路径与网络核查

总览的“配置位置”显示 Codex 实际读取的运行文件。例如默认入口为 `/root/.codex/config.toml` 时，连接共享数据目录后仍显示此路径，属于正常状态。数据与存储显示用户选定的完整数据目录；历史链接让新聊天直接写入那里，本环境的配置和认证缓存由插件按档案管理。

启动核查只检查本地设置、启动入口、绑定和恢复记录；不自动发出联网或模型请求。若独立 Codex 启动命令的注册丢失或被外部覆盖，显示核查异常，不自动覆盖用户设置，也不将待重载状态清为正常。

“测试连接”检查表单中代理到公共 HTTPS 页面是否可达，不会应用草稿，不等于官方账号登录或聊天生成通过。结果只保留在当前插件运行期间，重启后明确显示尚未测试。旧网络配置需要用户确认后重新应用并重载；普通刷新或重装不会自动迁移。

## 认证、环境识别和共享范围

| 数据 | 范围 |
|---|---|
| 官方账号档案、sessions、归档与 SQLite | 同一物理目录中，同一档案跨环境共享 |
| API 历史 | 所有 API Providers 使用同一档案 |
| config.toml、auth.json、当前账号、CLI 文件、网络设置 | 环境独立；账号配置与缓存进一步按档案独立 |
| Provider 定义/顺序及原 API Key 引用 | 保留原 globalState/SecretStorage；仅 Provider 列表参与 Settings Sync |
| providers/ JSON | 手动导出，不是第二个自动同步的配置源；不读取 SecretStorage 中的 API Key 或用量令牌，不包含认证和聊天；包含经过标准认证字段脱敏的模板、协议高级参数和用量配置。两个 Codex 导出入口格式相同，区别只有保存位置 |
| backups/ | 主动历史快照，排除认证与客户端配置，不自动循环创建 |

新环境首次绑定已有官方档案不复制任何其他环境的认证或配置，需自己登录。原环境重启/重连通过原环境 UUID 和账号 home 复用缓存；过期仍由 Codex 要求登录。文件凭据存储用于本环境隔离；组织强制 keyring 等策略可能限制此方式，需按官方策略处理。环境 UUID 使用扩展运行端磁盘 marker，结合 remoteName/hostname/home/OS；不是每工作区新建。若完整复制扩展存储和相同 hostname 等全部环境身份，将被视为同一逻辑环境；不要以这种克隆方式隔离认证。

绑定同一档案是用户显式选择，不是仅凭登录账号自动寻找任意磁盘中的聊天。其他环境新增档案/Provider 后点刷新可见；它们切换账号不改变本环境绑定。安装新 VSIX 后其他环境仍需各自安装相同新版；刷新不会分发扩展代码。

## 运行设置的操作确认

0.8.1 移除扩展/CLI 的运行中、空闲、未知检测，不再扫描进程或依赖 Codex 私有任务状态接口，也没有重试检测/两次强制流程。官方扩展后台进程存在不等于任务运行。

切换账号/官方/API 模式、应用 Provider/当前模型、改变协议转换代理、应用或恢复网络设置、启用/停用 Codex 管理、连接/迁移目录或恢复历史前，统一弹出一次确认。取消不执行该次运行设置更改；“保存并应用”先确认再保存。提示明确涉及当前环境的扩展和 CLI，请用户先等待任务结束，插件不会自动停止任务。查看、刷新、备份、导出以及单独保存 Provider 定义不额外询问。删除日志/Provider 保留各自删除确认。

用户确认不能消除其他进程同时写入的风险，也不能使现有客户端立即读取新配置。配置/绑定修改后按提示重载或重启。当前主要验收场景是跨环境接续使用，同一 SQLite 跨系统同时写入的兼容性仍需实机验收。

## 操作日志

即使尚未选择数据目录，也从插件启动开始记录。默认位置是当前扩展运行端的 `globalStorageUri/environments/<环境UUID>/logs`（VS Code 扩展存储，不是项目目录）；“数据与存储 → 操作日志”显示完整路径。该路径跨工作区/窗口重启保持；容器销毁且扩展存储未挂载时不会保留。

连接数据目录时，将此前操作日志复制并校验到 `ai_client_data/codex/environments/<环境UUID>/logs`，再持久化位置并删除已验证的旧副本。复制、校验或位置保存失败时原日志及原位置保留；账号目录绑定失败时也尝试恢复原日志位置。若另一窗口仍在旧位置写入，保留其源文件，待该窗口点击刷新状态后校验迁入；不删除活跃写入者唯一的新记录。意外退出可能留下重复校验副本，优先保留数据。

日志记录时间、插件版本、环境 UUID、操作编号/类型/区域、开始与结果、耗时、HTTP 状态等结构化元数据，以及错误类别、系统错误码、插件源文件位置和恢复结果。不会序列化完整操作参数、API Key、OAuth token、认证文件、请求响应正文或聊天内容。为避免服务端错误回显敏感内容，原始错误正文仅在操作区域显示，文件日志保留分类和代码位置。每文件约 2 MiB、操作日志总量约 10 MiB，旧文件轮换。

提供查看当前日志、顶部列表浏览、导出诊断及红色删除按钮。文件由插件直接在 VS Code 编辑器中打开，不调用远程 OS 文件管理器或更换工作区。删除确认只针对当前环境的操作日志和本窗口 VSCodeModelSwitch 输出日志，不删除配置、账号、聊天、备份或恢复材料。本次删除完成记录会成为新日志。旧版 VS Code 输出通道日志仍由 VS Code 管理；新操作日志不依赖输出通道是否打开。

## 失败恢复与迁移

Codex 不再每次 Apply 都生成 vscodemodelswitchbak。先准备完整内容，持久化本次旧文件和变更记录，再逐项替换；普通失败恢复文件、目录链接与活动绑定。成功标记后清理临时恢复点。旧配置存在/不存在的状态均保留，敏感文件使用私有权限；不会回退或覆盖新聊天。

进程异常退出后，下次启动检查恢复记录。其他进程改动了目标内容时停止覆盖、保留恢复材料并明确提示。恢复不完整会锁定后续 Codex 写入；操作确认不能绕过未解决的文件冲突。注册表编辑也使用持久恢复记录，活跃操作不会被另一个窗口回滚。该机制用于应用异常与进程退出，不能承诺任意断电、磁盘损坏或并发外部写入下完整恢复。

首次迁入 Linux 固定目录时，原历史子目录保留在 `CODEX_HOME/sessions.before-vscodemodelswitch-*` 等同级位置，原认证与配置保留在本环境的 `original-home-*` 私有初始副本中。旧的可替换根入口路径仍会保留整个 `CODEX_HOME.before-vscodemodelswitch-*`。这些首次迁入副本不是持续备份，验收后由用户决定是否清理。若历史子目录自身也独立挂载，无法重命名时明确报错并回滚，不修改挂载。旧版环境独占 identities.json 只在“连接/迁入目录”显式升级：可将当前环境的旧账号档案迁入空目标，各旧目录保留；不读取其他环境的认证。目标已有档案时只连接所选档案，不覆盖、不自动合并当前旧历史。旧版全局目录设置不会自动采用，用户需明确选择。已有 vscodemodelswitchbak 不自动删除；Codex 与 Claude 的新应用操作均使用短期恢复记录，不再持续生成该备份目录。

历史备份每次生成新的独立完整快照，不删除旧备份，不做增量或去重。浏览/删除入口列出档案、时间、大小和完成标记；未完成材料也可明确选择后删除，不操作活动历史。当前 UI 不提供恢复为新档案，用户可直接让 AI 读取备份聊天文件。目录内 readme.md 随首次初始化生成，已有说明文件不会被升级自动覆盖。

连接失败可能已完成档案准备，但尚未启用绑定。重试同一数据目录时选择已准备的账号即可；不会清空、重建或自动合并原历史。失败后继续在原目录产生的聊天仍保留在原历史子目录的首次迁入副本中，未自动进入之前已准备的共享档案。请勿删除旧目录，待确认账号和历史范围后再单独处理。

“另存为供应商配置”和“保存到数据目录”均只导出 Codex API 定义，不保存聊天或已存储的密钥。Codex 页面导入只更新 Codex 定义，不修改 Claude、不自动改变当前选择或写入客户端文件。历史备份、Provider 导出/导入、日志操作和输出位置本身不需要重载；改变当前活动绑定才需要。

## 0.10.1 Linux 宿主/容器不同 UID 的目录权限

旧版用 0700 创建共享 codex 根及 environments 等父目录，用 0600 保存公共 profiles.json；容器 root 与宿主普通用户 UID 不同时，宿主在建立自己的 logs 前就会 EACCES。这与官方/API 模式无关。新版先准备共享目录，再建立当前环境日志；公共目录使用 2770、公共注册表/历史使用 0660，各环境认证、配置和恢复缓存仍私有。

两端必须拥有同一个可信 POSIX 属组；本项目共享父目录已为 GID1000、setgid。共享 profiles/providers/backups 目录使用默认 ACL 让后续原生客户端通常以 0666/0777 创建的文件/目录保留组读写，避免 umask 再次阻断。Linux 需要现成的 setfacl/getfacl 及支持 POSIX ACL 的挂载；不自动安装或修改系统。原生客户端若主动 chmod 为 0600、不同属组或不支持 ACL 的共享文件系统，仍需单独解决权限；Windows ACL 不由本功能修改。

旧目录必须在创建它的环境，由其属主执行一次定向修复。安装新版不会擅自扫描或重设真实数据权限。以下脚本只访问共享层的权限元数据，不读取认证/聊天正文、不更改属主、不跟随历史树内的符号链接、不遍历 environments 的子目录；执行前保存完整权限/默认 ACL 快照。先结束使用该目录的操作，再运行（路径按实际环境替换）：

```bash
node scripts/repair-codex-storage-permissions.js /path/to/ai_client_data/codex /path/to/new-permission-snapshot.json --apply
```

失败保留快照；按相同路径将末尾改为 `--rollback` 可恢复本次权限及默认 ACL，恢复后旧 EACCES 也会回来。不要递归 chmod 整个 ai_client_data，更不要放开 environments/<环境ID> 内的认证。修复后宿主仍选择已有档案；API 模式可以直接连接已有 API 档案，不必先切官方账号。真实宿主窗口的连接/重载与 Chats 仍需实机复验。

API 模式连接已有数据根时，只列出现有 API 档案；若根中只有官方档案，提供“新建 API 共享历史并迁入当前 API 历史”。该选项需明确选择与确认，保留官方档案及其环境绑定，并把当前环境 API 配置留在当前环境。已有 API 档案仍只连接，不自动合并本地历史；并发新建发现 API 已存在时停止，不向已存在的库写入初始化历史。
