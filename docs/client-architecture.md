# 客户端模块与供应商群组（0.12.0）

## 原生 API 新会话来源（0.12.12）

app.applyProvider在attached API档案中将root/profile/env绑定交给两个适配器；适配器把API配置、来源上下文在同一FileRecovery事务发布，并保留用户hooks。historySources.ts生成稳定的SessionStart命令，historySourceHook.ts处理原生新会话事件，在profile/history-sources按会话ID发布不可覆盖收据。生产不修改native hook信任/策略，不监听新文件推断API，不介入网络请求。

HistoryLabels.model读取候选API会话收据，按创建时API名称合组，并附记录环境；手动placement优先、旧未知不补。model的revision仍基于已保存标签，不因读取预览自动写标签；收据名实体在用户保存标签时可一并保留。API profile、sourceKey、导入副本及原生索引协议不变。完整数据目录备份包含侧边收据，history-only不包含。

保存使用共享组事务和revision乐观并发检查，失败保留草稿/原记录；不同环境不能静默覆盖较新标签。history-catalog.json保留旧环境名称/关联事实，标签写在新sidecar，原结构/IDs不迁移。全数据目录备份保留标签，history-only快照不含根sidecar。

Codex原生扫描全部分页/归档，私有SQLite仍在environments/<环境>/indexes/<档案>；旧索引显式升级。nativeIndex.ts只调用initialize/thread/list、所选thread/read与明确的副本thread/name/set/thread/delete，无登录、模型turn或SQL改写。删除后核对两种归档状态列表不存在该ID。生产不修改/加载官方extension.js；合成测试在内存导出Claude SDK读取器。

storage/historyPermissions.ts继续在写入端维护自己拥有的原生历史，不进入认证/配置/环境目录、不改他人属主或权限。history-imports/内保留内容使用创建时共享权限，不依赖系统守护进程。当前备份覆盖原生history树的可见副本；隐藏副本库及其registry不在现有history-only快照范围，需备份完整数据目录。

这是当前实现的维护入口。AgentDeck 仍是一个 VS Code 扩展，内部扩展标识和现有数据键保持。没有实现 WorkBuddy 的真实设置、网络或历史适配。

## 0.12.0 共享界面与原生认证

`shared/ui/providerPage.ts` 提供统一的供应商群组与表单交互；内置页面各自持有内存草稿、排序缓存和环境选择。公共 DOM 的旧 codex 前缀只是内部控件锚点，实际数据/操作按选中客户端路由，CSS 使用 managedPage。`shared/providers/controller.ts` 负责公共群组操作；两种后端存储命名空间独立。`clients/claude/profiles.ts` 与 `sessionController.ts` 管理原生配置目录和 projects 历史，保留原路径凭据，不复制 Codex 目录/SQLite 实现。共用历史快照工具按客户端限定文件树；Claude 不恢复 Codex 备份。目录、日志、登录提示及网络恢复见 management.md。

## 源码职责

- `src/clients/index.ts` 是内置模块组合入口；`shell/clientRegistry.ts` 注册客户端标识、名称、能力、消息处理器和页面贡献。导航从注册表生成，不把页面入口限定为两个工具。
- `clients/codex/` 拥有页面布局、群组操作、账号/历史、原生配置适配及官方诊断/测速；`clients/claude/` 拥有 Claude 页面、操作入口及其配置适配器。已有文件移动后只更新模块引用，不改变运行配置目录。
- `shared/clients/providerController.ts` 复用供应商/网络等公共操作分发，Codex/Claude 控制器的依赖接口分别收窄。消息里的工具和供应商归属在后台核对；Claude 的历史、群组和模式消息传入 Claude 专属后端，不能调用 Codex 模式切换或跨客户端供应商，未知操作不会空执行后显示成功。
- `shared/providers/` 负责群组元数据、导入计划和本环境可用性；`shared/ui/` 复用请求处理字段；文件恢复、日志、传输和现有 API 协议服务继续复用。`app.ts` 保留扩展生命周期、命令与这些服务的协调接口；它不是第三客户端必须实现的接口。
- 两个已有页面复用同一个表单组件，但各自持有内存草稿；页面切换不把供应商名称、密钥、模型和请求参数带到另一页面。密钥草稿不写入 webview 持久状态。网络草稿、折叠、操作提示及禁用状态有各自客户端/环境范围。

## 接入新客户端

新建 `clients/<client-id>/`，实现注册表 `ClientModule`：唯一字符串 ID、名称、能力、`handle`，以及可选浏览器页面 `browser`。在组合入口注册。独立页面提供 `markup`、定义页面类的 `script` 和 `controller` 类名；`render(state, busy)`、`enter/leave`、`receive` 是页面生命周期约定。用 `clientAction` 携带该客户端自己的操作与数据，处理器可以回复自己的状态，不需要借用 Codex/Claude 的专属操作。

新增页面的控件 ID 使用 `<client-id>-` 前缀，控制器类名唯一；注册时检查，避免遮蔽公共按钮。浏览器代码与页面贡献是仓库维护代码，不加载任意外部脚本。现有 `ToolId`/协议适配类型描述当前两个内置 API 适配器，并不限制注册表客户端 ID；新客户端若复用 Provider/网络后端，应为其补齐协议和配置适配，不能把它当成 Codex 或 Claude 去写文件。没有动态插件加载、占位 WorkBuddy 功能或一套额外依赖框架。

## 两客户端群组和排序

默认群组“独立供应商”初始排第一，之后可移动。允许空群组。群组名在当前客户端内唯一；供应商名在整个当前客户端内唯一，跨群组也不能同名。名称比较忽略首尾空白、英文大小写和 Unicode 全半角差异。Claude 的名称空间独立。

按住群组标题或供应商卡片的非控件区域约 350 毫秒后拖动；标题行 ON/OFF 控制启用状态，↑/↓ 每次只移动一位。同分区首尾的对应箭头禁用。供应商支持组内排序和跨组移动，“移动到群组”提供选择列表。启用与禁用分区分别排序，禁用项目总在末尾；恢复后重新按已保存顺序排列。群组折叠状态按环境保留。移动只改变归属/顺序，不改连接、模型、Key 或实际客户端文件。

单个供应商禁用后只保留恢复和原组排序；所在群组禁用后，组内配置/模型/用量/测速/协议操作都不可用，但仍可查看、排序及接收新的供应商。群组恢复不改变成员各自标记。当前供应商禁止单独禁用；禁用包含它的群组要求确认，并明确当前 Codex 继续使用已应用配置，不切换、不停止、不撤销 Key。该状态仍在群组和总览可见。禁用是 AgentDeck 的本环境操作限制，不是服务器账户停用或进程出网拦截。

## 群组设置模板与网络

“新建群组”右侧的“群组设置模板”管理可复用模板，支持新建、载入编辑、保存和删除。每份模板包含 API 请求处理（直连/兼容代理、协议和参数）与 API 余额查询规则（预设、接口地址、JSON 路径、单位和数值除数）。模板不包含默认 API 地址、模型、API Key、余额管理令牌或管理用户 ID；余额地址可以使用 `{{baseUrl}}` 引用成员的 API 地址。原请求处理模板保留可复用参数，余额查询默认为关闭，不重写旧存储。

群组设置包含可选默认 API 地址、请求处理和余额查询规则。可从模板载入后再调整。保存群组只修改默认副本，不追溯覆盖已有供应商；删除模板不影响群组和供应商已载入的副本。

新增供应商表单保留名称、API 地址、Key、模型选择或完整配置文本，仍支持获取模型与保存后应用。群组只是选择项，不显示请求模式、连接设置或载入模板按钮。选中有默认地址的非独立群组时自动填写地址；保留用户手工修改的地址，切换到无地址群组时清除旧的自动填写值。后台创建时复制所选非独立群组已保存的请求处理及余额规则；独立供应商或未保存设置的群组使用普通默认值。模型可稍后填写，其余原有必填和去重规则保持。

已有供应商点击“载入群组设置”，复制默认 API 地址（若有）、请求处理及余额规则到该供应商的编辑草稿；保留 Key、模型、管理令牌与管理用户 ID。仍需检查、保存，再明确应用。移动群组只改变归属，不载入设置；修改模板或群组不会自动应用客户端配置。

网络统一在主界面设置。预设编辑框将代理地址、绕过代理目标和名称/备注放在同一视觉区域；保存、载入、复制和粘贴包含绕过列表。载入只填草稿，明确应用才替换当前客户端路由。供应商切换和群组设置不应用网络，不影响其他客户端路由。旧群组网络引用不再出现在视图或操作中。

删除非独立群组后，成员移回独立供应商，保留成员自己的启用/禁用标记、配置和相对顺序；原组被禁用不等于成员被单独禁用。当前选择与已应用配置保持。独立供应商群组不可删除。

## 持久化与导入导出

- 原 Provider 列表与密钥引用保留。首次没有群组元数据时，现有供应商按默认群组显示；不重建 ID，不改 Key，不写客户端。
- `vscodemodelswitch.organization.<客户端>` 分别保存群组、顺序、成员关系和模板；它与原 Provider 定义一样属于共享元数据并可参与 Settings Sync。
- 禁用标记在环境命名空间中保存，不参与跨机器同步；当前供应商和真实 CLI 配置仍独立。两个客户端不共用群组命名空间。
- 两个 Codex 导出入口均为 v2 JSON，包含完整群组（含空组）、成员和模板，以及脱敏 Provider 定义；不包含禁用状态、网络入口、认证缓存或 SecretStorage 中的 Key。`providers/` 仍是主动导出目录，不是自动配置源。
- 支持 v1 导入，保留现有群组元数据；新版导入先完成名称、归属和 ID 冲突检查。合并/替换仅作用于当前页面客户端，不更改当前选择或自动应用。定义/群组写入失败尝试恢复此前两份元数据；恢复不完整明确报错，不表示导入成功。
- 导入、群组、排序、禁用和模板保存不要求重载。真正应用网络、模式或历史绑定仍按原有确认/重载规则执行。

## 历史不随 API 群组拆分

所有 API 群组和供应商仍共用同一个 API 历史档案。已有数据目录中，点击“切换到 API”会复用或建立唯一 API 档案，重载后应用供应商。另一个环境连接同一物理目录时选择已有 API 档案，不另建同名目录。官方账号各自的历史保持独立；新环境认证不复制。目录详见 management.md。

此前 Codex 原生 Linux fixture 增加 API-A/API-B：不同 API 地址和合成密钥、同一 API 档案，在默认供应商过滤下两环境都列出并读取两条历史，官方历史不混入。不发模型请求；不是宿主机真实图形界面或跨 Windows/Linux 挂载验收。

## 平台和验收

Linux 隔离测试包含第三客户端注册/视图/消息夹具、群组 UI、禁用保护、模板副本、v1/v2 导入及故障恢复。Windows 原生网络启动器仍未实现；WSL、真实账号/聊天/两客户端图形界面和跨OS挂载未实测。没有修改真实代理、账号、绑定或历史。安装后先检查迁移后的原列表，再用空群组/非当前供应商验收拖动、模板和禁用；当前群组禁用确认不停止真实任务。

## Codex 视觉层级与编辑草稿

页面模块、功能分区、供应商群组、供应商卡片、编辑内容通过递进字号、留白、背景深浅和边框区分；背景随 VS Code 主题变化。蓝色用于当前项及编辑归属，ON/OFF 与告警保留独立状态语义。模型、诊断和高级请求字段使用轻量分隔，避免每层都是同样的完整边框。

供应商配置嵌入所属卡片，标题标明供应商名称；群组设置放在组内，模板管理位于供应商区顶部。刷新、折叠和关闭重开当前供应商编辑器会保留原始输入草稿，包括尚未合法的参数文本。草稿只在当前 webview 内存中保存，不写入持久 webview 状态；取消编辑恢复原配置，关闭窗口会丢失草稿。

当前供应商的 ON 开关不可直接关闭；含当前供应商的群组关闭仍需确认，已应用配置继续运行。开关及箭头不触发折叠或拖动，短按和取消长按不发移动消息。

## 0.11.1 状态与边框

Codex 注释使用统一蓝色竖条及轻微底色，模块/分区/卡片/内层设置采用递进深浅的蓝灰边框。当前官方账号与 API 使用较粗的实色蓝框、蓝色“当前使用”标记与状态按钮；仅打开编辑器不会将普通供应商外框标成当前项。未应用 API 的“应用”是普通按钮，当前且无更改时是不可重复点击的“当前使用”；当前但有待应用修改时仍保留标记，按钮显示“应用更改”。官方账号绑定待重载时不显示“当前使用”。

网络状态“已应用代理”表示本环境记录的独立路由已应用且本地核查无异常，不代表真实聊天已成功。未配置或尚未迁入独立路由的旧配置显示“未应用代理”，核查异常单列；修改预设草稿不改变已应用标记。配置核查异常时允许重新应用，应用仍走原确认流程。
