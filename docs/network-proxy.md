# 独立聊天网络设置

## 已应用配置与编辑草稿

Codex 和 Claude 页面均在“已应用代理”旁显示本客户端实际已应用的备注、代理入口和绕过地址。应用时有备注就显示该备注，无备注显示“临时设置”；是否保存为预设不影响这一规则。未应用、旧配置待应用或核查异常时不展示为已应用摘要。

编辑、载入、粘贴或保存预设只改变草稿，摘要保持当前实际配置；明确应用成功后才更新摘要。切换客户端分别显示各自配置，停用后清除摘要。停用并重载后应显示“未应用代理”，停用按钮为“已停用”；输入框可保留代理地址和绕过列表草稿。0.12.4修复旧版遗留受管标记导致的红色误报，无需重新应用代理。真实恢复错误仍会明确报警；停用是恢复应用前字段，不保证原值、启动环境或VPN本身无代理。它表示 AgentDeck 已配置的路由，不是实时公网出口 IP 探测。

0.11.0 起，群组不保存或载入网络预设，所有网络设置集中在本模块。预设的同一编辑区域包含代理地址、绕过目标和名称/备注，保存/载入/复制均包含绕过目标；载入只修改草稿，明确应用后才替换本客户端路由。

ModelSwitch 为 Codex 和 Claude Code 分别保存当前环境的 HTTP 代理入口和绕过列表。不启动 VPN、不选择远端节点、不更改系统路由或防火墙，也不修改 VS Code 扩展宿主的 `process.env`。本版本不再为 Codex 设置共享的 `http.proxy`。

## Claude Code：原生代理、账号目录与 CLI

Claude 使用官方支持的 `settings.json.env` 中的 `HTTP_PROXY`、`HTTPS_PROXY`、`NO_PROXY`（以及对应小写变量）。本环境只有一套 Claude 网络设置，应用时更新当前目录及本环境已经准备的账号/API 目录；新目录在切换前接入相同路由。代理不保存在供应商群组、模板或账号共享注册表中，不随供应商或账号切换改变。停用恢复各目录原有的受管字段，保留其他设置、API 配置和原生凭据。

`claudeCode.environmentVariables` 保留相同的代理镜像，覆盖扩展启动继承的大小写代理；本地核查检查镜像及所有受管文件，外部修改产生冲突时拒绝覆盖。`ALL_PROXY/all_proxy` 清空，避免另一代理入口产生歧义。配置目录使用原生 `CLAUDE_CONFIG_DIR`，不修改扩展宿主 `process.env` 或 VS Code 共享 `http.proxy`。没有代理失败后改为直连或自动换节点的实现。

扩展和 VS Code **新终端**使用同一档案选择；终端环境集合只写 Claude 配置目录，不向所有终端注入 API Key 或 HTTP 代理。原生 CLI 从该目录读取网络设置。通过 AgentDeck 启动的 CLI 同样携带已选目录与本客户端路由。已有扩展后台/CLI/终端可能保留旧环境，切换后须重载扩展并关闭、重建旧终端。

外部终端不由 VS Code 的终端环境集合控制：须使用“数据与存储”显示的 `CLAUDE_CONFIG_DIR` 后运行已安装的 `claude`。首次接入的默认档案保留“变量未设置/为空”的语义；返回它时外部终端也应保持变量未设置或为空。仅把默认路径显式写入变量可能改变原生全局状态位置及系统凭据库命名空间，因此插件不这样改写默认档案。

API 模式仅隐藏原生第三方认证提示，返回官方模式恢复提示能力；不通过这个开关伪造登录成功。若外部环境仍有 API Key、第三方地址或认证覆盖，官方切换会指出变量名并停止，不输出值或删除用户配置。项目/组织策略或外部启动器的更高优先级配置仍可能影响结果，必须在原生客户端确认。

**浏览器授权页面使用浏览器自己的网络**。扩展、CLI 的代理配置不能控制宿主浏览器；首次登录请分别确认客户端及浏览器的出口。代理地址稳定不等于公网出口 IP 稳定，出口由代理/VPN 服务管理。本功能不能保证账号不会受到限制，也不是操作系统级的所有进程出网隔离。

依据：[官方网络配置](https://code.claude.com/docs/en/network-config)、[扩展设置](https://code.claude.com/docs/en/vs-code#extension-settings)、[多账号原生目录](https://code.claude.com/docs/en/authentication#log-in-with-multiple-accounts)。本阶段另核对已安装 Claude 扩展 2.1.322 的目录/凭据命名规则；跨平台真实登录仍待验收。

## Codex：Linux 实验性独立入口

当前官方扩展通过 `http.proxy` 注入后台代理，却没有与 Claude 对等的专属代理环境变量设置。`chatgpt.cliExecutable` 又是 application 作用域，不能让宿主和容器各写一个不同绝对路径。

本版使用统一命令名 `vscodemodelswitch-codex` 注册该入口，在每个 Linux 环境的官方 Codex 二进制目录新增一个生成的启动脚本。已核对的官方扩展会把自己的二进制目录追加到后台进程 PATH，因此同一个命令名在不同环境解析到各环境脚本。脚本只给自己的原版 Codex 子进程提供代理变量，保留参数、工作目录、CODEX_HOME、标准输入输出和退出状态。官方二进制及扩展 bundle 不被替换。

这是共享的启动注册，不是共享的代理地址。每个环境的路由值仍各自保存。新 Linux 环境发现该注册时，会准备自己的脚本；未在该环境启用代理时准备不覆盖环境变量的直通脚本。检测到同名 PATH 冲突、用户自定义启动程序或非受管文件时拒绝覆盖。脚本需要当前用户对官方扩展二进制目录有写权限。首次注册会明确提示兼容性范围；入口被加入 Settings Sync 排除。

**重要限制：同一 VS Code 客户端使用该公共注册的其他环境，也需要安装并启动 ModelSwitch。Windows 原生可执行入口未实现；Windows 窗口直接启动 WSL 后台、以及直接连接 WSL 窗口尚未原生验收。混合 Windows/Linux 客户端不要启用此实验入口。首次进入新环境或官方扩展升级后可能需要重新加载；版本兼容与升级仍需原生验收。**

停用 Codex 时把本环境脚本恢复为不注入代理的直通入口；保留公共命令注册以免影响其他仍使用它的 Linux 环境。恢复的是代理行为，不表示删除公共启动注册。所有环境均停用、准备卸载 ModelSwitch 时，应在 VS Code 设置中清除 `chatgpt.cliExecutable`，恢复官方默认入口。

## VS Code 共享代理与独立代理：四种组合

`@id:http.proxy` 是 VS Code 设置页面的搜索条件，实际设置项为 `http.proxy`。它是编辑器共享代理入口，当前已核对的官方 Codex 扩展会读取其有效值，传入聊天后台进程；其他遵循此设置的 VS Code 功能也可能受到影响，它不是系统级的全部流量开关。

新版 AgentDeck 在 Codex 启动脚本中为该后台单独设置 HTTP(S) 代理和绕过变量，已应用时覆盖后台继承的代理变量；停用后使用不注入代理的直通脚本，后台仍可继承官方扩展传入的共享代理或其他环境代理。新版不再为启用独立代理而写入共享 `http.proxy`，也不修改扩展宿主的 `process.env`。

下表按当前已核对的 **Linux Codex 扩展聊天后台**说明；取操作完成后 `http.proxy` 的最终有效值，且客户端后台已重新启动、请求未命中绕过列表。A、B 可以是不同地址，也可以相同。

| VS Code 有效的 `http.proxy` | AgentDeck 独立代理 | 聊天后台的代理情况 |
| --- | --- | --- |
| 未设置 | 未应用 | 使用继承的环境代理或直连；系统 VPN/TUN 仍可能提供网络 |
| 代理 A | 未应用 | 官方扩展会传入 A，因此停用 AgentDeck 后仍可能通过 A 联网 |
| 未设置 | 已应用代理 B | 使用 AgentDeck 为后台设置的 B |
| 代理 A | 已应用代理 B | 后台使用 B；其他遵循 VS Code 共享设置的功能仍可能使用 A |

“已应用”指明确执行应用并按提示重新加载客户端。只填写地址、载入/保存预设或测试连接不改变聊天后台的既有路由；已有后台进程也可能保留启动时的代理。测试连接是按草稿发出的独立探测，不证明聊天后台已使用该路由。

停用 AgentDeck 不等于强制直连或断网；清空 `http.proxy` 也不能排除环境代理或系统 VPN/TUN。绕过列表检查目标主机，命中时不经过对应 HTTP 代理。表格描述聊天后台的代理变量；若请求先到本地兼容转发服务，最终上游连接还取决于该服务自身的网络配置。上述规则不作为 Windows/WSL 或其他客户端的未验证承诺。

如果两处都填写同一个地址，例如 `http://127.0.0.1:12000`，单凭请求成功或失败不能区分实际代理来源。新版独立代理应用成功，也不等于旧共享设置已全部恢复；旧设置恢复范围见“旧版迁移与失败恢复”。

## 启用、复制与预设

1. 选择对应工具页面，填写 HTTP 代理入口、绕过目标与备注。预设端口仅为示例，不保证与 VPN 软件一致。
2. 复制/粘贴和选择预设只更改草稿。自定义预设按工具和环境保存，不自动应用。
3. 测试连接只检查传输，任何 HTTP 响应都不代表账号、额度或聊天成功。
4. 应用或停用前，先结束当前客户端中的运行任务并确认。成功后按提示重新加载，等待状态由下一次启动的本地核查清除。
5. 最后在原生插件和 CLI 验证实际聊天；这些验收不能由 ModelSwitch 的探测替代。

`localhost,127.0.0.1,::1` 是三种本地目标写法。绕过列表检查最终目标，不检查代理服务器本身。例如访问 `https://api.example.com` 时可交给本地 `http://127.0.0.1:12000` 代理；访问本地兼容转发接口时不经过代理。Linux host 网络容器与宿主共享网络空间，可访问相同回环入口；隔离网络容器通常需要宿主可达地址。

## 旧版迁移与失败恢复

旧版配置不会因安装就自动迁移。状态明确提示重新应用或停用。对应工具的显式操作只会按当前环境可识别的备份恢复旧版接管字段；外部改动冲突时保留现场。最早版本没有环境前缀的全局网络备份目前未自动迁入，因此“已应用代理”不能单独证明所有旧共享字段已恢复。应先确认旧字段归属和修改前值，再恢复；恢复原值不等于一律清空已有用户代理。Claude 操作不恢复 Codex 字段，反之亦然。

文件修改使用短期 FileRecovery 记录，原设置的受管字段与未完成的设置恢复记录保存在环境专属 SecretStorage。成功后清理临时材料；失败按原值恢复，恢复未完成时保留记录和持续错误状态。启动/手动刷新检查恢复记录；不会把未知或冲突状态伪装成成功。不要手动删除未解决的恢复材料。

## 验证边界

Linux 合成配置验证覆盖独立应用/停用、共享启动注册、多环境状态、CLI 配置、参数传递、原环境变量不变、外部修改与失败恢复。原生 Codex 和 Claude CLI 的实验使用隔离空目录、合成凭据及本地错误响应，仅证明请求连接到指定入口，不证明真实账号聊天成功。Windows/WSL 与实际图形界面、真实登录验收另行进行。每次更新的缺口见源码仓库 [开发日志](development-log.md)。

## 0.9.1 界面调整

网络模块优先显示“测试连接”“启用代理/应用更改”“停用并恢复”三个操作，随后显示状态和填写项。复制设置会把当前草稿的 HTTP 代理入口、绕过列表、备注及工具标记写入剪贴板；粘贴会改为当前页面的工具标记，并只填入草稿，仍须手动应用。固定回环绕过项会规范化保留。不会复制账号、API 密钥、历史或代理启停状态，也不会批量复制所有自定义预设。

本轮只调整文案与控件位置，不改变 0.9.0 的路由、恢复和平台限制。

## 0.9.4 状态说明与按钮位置

状态徽标在上，测试连接、启用/应用更改、停用恢复三个按钮紧接其下。总览“旧网络配置，待重新应用”表示本环境的该工具保存了代理记录，但没有新版独立路由的应用标记；不是网络测试失败，也不表示新版实现没有测试。另一工具完成迁移不改变当前工具标记。安装、刷新状态和测试连接均不会替用户迁移运行配置。

确认当前任务已结束后，在对应工具页面检查地址并点击“应用更改”，确认操作并按提示重载；成功后显示“独立路由配置”。若本地核查错误，总览提示“配置核查异常”。连接探测、已保存的配置方式、真实客户端聊天是否成功是分别判断的。新版原生Linux入口测试已在0.9.0合成目录/凭据/本地503夹具中通过，不是当前用户真实登录或VPN聊天验收；本轮只调整UI，不重复原生路由测试。
